# W3: live-set job store and a doctor that does not block (Tide arch-10-22, wave W3)

Every scan of the kitchen read every order ever filed: 290 job files today, ~2,840 at 10x. The doctor held the state lock for its
whole run, backups and watchers included, so an approve or add could wait seconds. Now:
- **Live set**: `kitchen/jobs-lib.ps1` keeps `jobs-index.json` (status, parent and Chef flag of each `jobs\` file, keyed by its size and
  write time). A tick opens only orders still in play (not done or closed). The index is never trusted blindly: a changed file is read
  again, a missing or damaged index is rebuilt from the files and logged (`jobs.index.rebuilt`).
- **Archive**: the doctor moves done and closed orders untouched for 3 days (`archiveDays`) to `jobs\archive\yyyy-MM\`, after one summary
  line each in `jobs\archive\index.jsonl`. Running it again is safe; moving a file back to `jobs\` restores the order.
- **Readers**: ledger, scoreboard, ideas, diagnose, freeze-lib, roadmap-lib, handoff and undo-merge read through jobs-lib (live set, plus
  archive summaries or archived files where they need history). A lint test keeps every other script from listing `jobs\`.
- **Next-Id** from `jobs\next-id.txt`, checked against `jobs\`, the archive and `corrupt\` (an id is never given twice).
- **Doctor lock**: held only to read the jobs, to archive and to write supervisor.json. The backup, prunes and watchers run outside it.
  The `doctor` event carries `ms` and `lockMs`.
- **Backups**: `backups\daily\yyyyMMdd` (7 newest days by the date in the name) and `backups\manual\` (hand-made, 14 days). The old
  layout is moved over on the first run. The off-drive copy (`scripts/backup-state.ps1`) now includes the archive.
- **Caps**: `maxJobs` 100 (refused adds) is now `maxLive` 100 (orders under way; new ones wait on the rail) plus `maxQueued` 2,000
  (adds past it are refused). `-MaxJobs` and a kitchen.json `maxJobs` still work, read as maxLive.

## Effect
- L1 (person): Jordan's taps never wait on the hourly doctor; 150 orders filed at once all queue instead of 50 being refused.
- L2 (business): a tick costs the live orders, not the whole history, so 10x the orders does not mean 10x the tick.
- L3 (MSP): lock hold time is a logged number (`lockMs`); backups keep 7 real days whatever sits beside them.
- L4 (community): the store contract is one small file (`jobs-lib.ps1`) with its format in the header.

## Not done
- Chef (`pass-app/server.mjs`) is unchanged: it already lists only `jobs\` top level (the live set). A Chef link to an order archived
  more than 3 days ago shows nothing; its history views read the live set only.
