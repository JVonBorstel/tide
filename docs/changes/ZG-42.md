## What it does

**The Spec** (`kitchen/recipes/lobe-rem.json`) is one night in four Steps, each its own bounded `lobe` Step with `retries 0`:

| # | Step | Limit | What it runs |
|---|---|---|---|
| 1 | `lobe.ps1 -Cmd rem` | 1800 s, 2000 MB | governor check, actions run, claims run, edges run, trust run, decisions prepare, **rem** (ZG-28), causal run |
| 2 | `lobe.ps1 -Cmd memory-check` | 300 s, 1500 MB | `scripts/memory-check.ps1 -Quiet` (read-only report) under `scripts/run-bounded.ps1` (240 s, 1000 MB) |
| 3 | `lobe.ps1 -Cmd memory-truth` | 300 s, 1500 MB | `scripts/memory-truth.ps1` under `scripts/run-bounded.ps1` (240 s, 1000 MB) |
| 4 | `lobe.ps1 -Cmd csf` | 300 s, 1500 MB | **csf** (the frame), then brief (FRAME.md); reads the archive result; closes the night |

The rem Step's limit went from 900 s to 1800 s: it now also holds decisions prepare and causal run (at most 3 trees of 120 s each).

**sleep[] (ZG42-1).** The rem Step opens the night in `<kitchen>\lobe\sleep.json`, tied to its work order (`KITCHEN_JOB`). Each later
Step of the same work order adds its entries. Each entry is `{step, exit, ms, state, why?}`. `state` is one of:
`ok`, `failed`, `waits`, `off` (not turned on), `absent` (not in the checkout yet) or `unknown`. After every run of the lobe Step, the
night is copied into `watch\lobe.json`:
- `sleep[]`, plus `sleepNight`, `sleepClosed` and `sleepFailed`;
- a failed step is added to the heartbeat's `error` as `sleep: memory-truth (exit 3) failed`, next to zeitgeistd's own words, so the
  Watch names it.

zeitgeistd rewrites `watch\lobe.json` on each of its runs. The lobe Step puts sleep[] back after each one, without doubling the words.
The heartbeat's own fields are rewritten byte for byte as strings, so `lastRun` is never turned into another date format.
A heartbeat that is not JSON is left as it is, and that is said.

**A failing memory Step never stops the frame Step.** The memory Steps always exit 0 with `lobe: memory-truth done exit=3 ms=N`. Their
real exit code goes into sleep[] and the heartbeat's error, and the line `memory-truth FAILED inside the night: drift found` is in the
Step's log. A hung script is cut by run-bounded at 240 s (exit 124) before the Yard's 300 s limit would fail the Step. A missing script
is a named failure (`exit=none`). Inside the rem Step, a failed night step (for example edges run) is named the same way and the rest
still run. Only the core (`zeitgeistd.rem`, and `zeitgeistd.csf` in the csf Step) decides the Step's exit code.

**The archive (ZG42-2).** The Yard's archive and backup retention (`kitchen.ps1` Invoke-KitchenJobArchive and Invoke-BackupRetention)
are **not moved**. They stay in the doctor, which the Site cleanup (`kitchen.ps1 chores`) runs once an hour. The csf Step reads the
doctor's last report (the last `doctor` event in `<kitchen>\events.jsonl`). It lists it in sleep[] as one of:
- `archive: done by Site cleanup at <time> (archived N work orders; backup retention reported no problem)`;
- `archive: Site cleanup at <time> reported: <the archive or backup problem>` (state `failed`);
- `archive: unknown (...)` when there is no report.

The Blueprint writes `done by chores`. The display word is "Site cleanup" (GLOSSARY.md maps that old word to Site cleanup).
Nothing outside the lobe database is deleted by this Spec. Test-LobeStation asserts the step list, that no Step and no rem argument
carries a delete, prune, purge, restore or remove flag, and that no module named for archive, prune or backup is run.

## Wrap, not replace (ZG42-3)

"Wrap, not replace" here means the night **runs** memory-check and memory-truth and **reads** the archive's result. It adds one report
(sleep[]). It takes no duty away from anything, and it changes none of their checks, outputs or exit codes. These still run on their
own schedule, exactly as before:

- **memory-truth: hourly.** It has no task of its own. The doctor runs it in its watcher list, and the Site cleanup runs the doctor when
  `lastDoctor` is 60+ minutes old (ZG-38's note). The night's run is an extra one at 4 am. Both write `watch\memory.json`.
- **Kitchen-Chores: every 2 minutes** (the Site cleanup). The doctor's archive, prune and backup retention stay there.
- **memory-check**: no schedule of its own (a search of this repo finds no task or Spec that runs it; Test-BrainMonitor tests it). It
  is run by hand as before. The night adds one read-only run.
- **lobe-sweep: every 2 hours** (ZG-07's standing line, not changed).

While the Yard is PAUSED, none of these run (ZG-38's note: a paused Site cleanup stops before the doctor).
