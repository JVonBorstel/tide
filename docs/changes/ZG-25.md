# ZG-25: Decision and post-mortem cards on the Board; Ledger flags 'decision-ready' and 'post-mortem-due'

Floor ZG-25 of Site ZG. Size M. Branch `zg-25-decision-cards`, built 2026-10-24 (MT). Stacked on ZG-30 (PR #104), which sits on
ZG-13 (PR #102) and ZG-09 (PR #92): it merges after #92, #102 and #104. Depends on ZG-24 (merged in zeitgeistd as `0bbd97e`).

## In plain words

- **The Decisions card is now the Owner's.** Each decision node waiting for you shows its question, the A and B steelmen, and four
  taps: A, B, Neither, Ask more. All four look the same: nothing is marked better (Law 1). The Board asks once more before it sends.
- **Post-mortems.** Each check that is due (day 30, 60 or 90) shows what you chose, the Ledger's proof, and three taps: Held up,
  Didn't, Unknown, with the date after which the lobe records "unknown" by itself.
- **The Ledger's proof** for a Sign-off (a decision about a work order): "still on main: commit abc1234", "undone", or "replaced by
  J150". A lobe decision has no work order, and the card says so.
- **A signal's three causal hops** fold open on a tap ("What could follow: 3 hops").
- **The Ledger** counts them in its top line, right after "waiting on you": `1 decisions ready, 6 post-mortems due`. Each is a flag
  for Jordan (pri 2), so the Ledger tab's badge counts it.

## What it does

**Board (`pass-app/server.mjs`, one block after `lobeAct`).**

- Reads `<lobe home>\flags.json` (ZG-24 `decisions run` writes it whole), the frame's `unlocked_choices` for the A / B words, the
  Ledger's `post-mortem-due` flags for proof, and the Owner's own taps.
- Files only, memoized by `sigOf`, inside `state.lobeOwner.decide`. A change to any of them reaches open phones as a patch.
- Writes only on an Owner tap through `lobeAct` (POST `/api/lobe`: the approvals' auth, origin check and body cap):
  - `{op: "decision", decision, choice: A|B|neither|ask-more}`
  - `{op: "postmortem", decision, choice: held|didnt|unknown, day}`
  - Both are one pass-actions.jsonl line in `tap_line()`'s shape. zeitgeistd `actions.tap_problem(line, require_ts=True)` returns
    `None` for all three kinds (run by hand with `uv run --offline python -I`).
- Refused:
  - a choice outside the lists;
  - an id not in flags.json;
  - a post-mortem for the wrong day;
  - a second answer since the lobe's last run (flags.json `updated`).
- A tap the lobe ran on and refused leaves the node in flags.json, so it can be tapped again. The proposal path of ZG-13
  (`decision` with `proposal`) is unchanged.

**View (`pass-app/public/lobe.js`).**

- `decideCard` replaces the read-only Decisions card when the Owner part carries `decide`. It also shows with no frame, because
  flags.json needs none.
- `causalHops` shows up to three hops of a signal's `causal_3rd_order_opening`.
- `wireWorld` handles the two new taps through its one `send()`.
- Missing or unreadable flags.json: an UNKNOWN badge with the reason, never "nothing waiting".

**Ledger (`kitchen/ledger.ps1`).**

- Reads `<lobe home>\flags.json`, the same home as the Board: `ZEITGEISTD_HOME`, else `<kitchen>\lobe`.
- Flags `decision-ready` and `post-mortem-due` (owner Jordan, pri 2), with ids, days and dates only. The question text stays on the
  World tab.
- Proof comes from what the Ledger already reads:
  - a `merge.undone` event, or a newest commit on main naming the order that is a revert: undone;
  - `replacedBy`: replaced by Jnn;
  - a commit on main naming it: still on main;
  - otherwise unknown, with the reason.
- `counts.decisionsReady` and `counts.postMortemsDue`, and `lobe: {ok, why, updated, ...}`.
- Missing flags.json: counts `null` and the top line says "decisions unknown". Unreadable: the same, plus a `lobe-flags-unreadable`
  flag for Claude. The Ledger never writes flags.json.

## Decisions (each a choice, not a guess)

- **The A / B words come from the frame only** (csf.py `unlocked_choices`, top 3, 40 characters each). The Board never opens the
  database. A node outside the top 3 shows its question and no tap until it is in the frame. Picking blind is not a tap.
- **"Already answered"** means a tap after flags.json's `updated`. zeitgeistd drops an applied node from flags.json; a node still
  there after a run was refused, so the Owner can answer again.
- **The Ledger's top line** carries the counts, and the flags carry owner Jordan, so the Ledger tab's badge counts them. `app.js`'s
  "need you" button is not changed: app.js belongs to ZG-17 in this stack.
- **Ids only in ledger.json.** A decision's question is lobe text, and the Ledger is read by more than the Board.
- **The causal tree's shape.** ZG-26 is not built. ZG26-3 names the csf field `causal_3rd_order_opening` but not its shape. The
  Board accepts a list of up to three strings, or one string with "->" between hops. Any other shape shows nothing.
- **No push.** Nothing new is pushed. A decision waits on the World tab and in the Ledger's count.

## Unknown or not verified

- **No real lobe yet.** No real flags.json exists until zeitgeistd `decisions run` runs (ZG-24 "For the Owner"). Only synthetic
  files in decisions.py `flags()`'s shape were used.
- **Causal hops have no source yet.** ZG-26 (`causal.py`) is not built, so the hops show only when a frame carries them.
- **Proof for undo by hand.** "Undone" is known from `merge.undone` events and from a revert commit that is the newest commit
  naming the order. A hand revert whose message does not name the order is not seen.
- **No browser check.** Not opened in a browser or on a 360 px phone; the markup is checked as strings. The live Board on 7878 was
  not touched.
- CI: see the PR.
