## In plain words

The World tab has a new Trust card. It shows, by numbers only, how often each one was right: the Foreman, every crew model,
the subcontractors and the world's sources. Each row has its Brier (0 = always right, 1 = always wrong), how many claims it is
counted over, and an arrow for the last 7 days. A number with no data says "unknown" and why. When the lobe wants to move a
source's trust by more than it may move it alone, that change waits on this card as a Sign-off: Apply or Drop.

## What it does

**Server (`trustView`, inside `state.lobeOwner.trust`).** Four files, each read only when its size or time changes (`sigOf`),
never the lobe's database, never a child process:

| File | Writer | What is read |
|---|---|---|
| `<lobe home>\trust.json` | zeitgeistd `trust run` (ZG-39) | each family's status (fixed words), `brier`, `n`; the Foreman's `claims`; world `sources_scored`, `sources_mean_trust`; crews and builders `members` |
| `<kitchen>\scoreboard.jsonl` | `kitchen/scoreboard.ps1 -Record` (ZG-22) | the newest line's `brier` (value, claims, pending, inspector, builder, models) and the newest line at least 7 days older (the trend) |
| `<kitchen>\watch\memory.json` | memory-truth | `unproven` (ZG-38), else `warn`: a count only, never the warning lines |
| `<lobe home>\signoffs.jsonl` | zeitgeistd claims.py (ZG-20) | pending Brier Sign-offs: id, status, trust from / to / delta, created |

Only numbers, ids, kinds and fixed words leave the server. trust.json's `line`, a claim's `statement` and the Watch's text are
never sent. A source's name and id are sent only when the lobe marks the Sign-off P0; a P1 or P2 source shows as "a P2 source".
`<lobe home>` is `ZEITGEISTD_HOME`, else `<kitchen>\lobe`; a protected home is not read.

**Tap (ZG40-2).** Apply / Drop on a Sign-off posts `{op: 'decision', signoff, choice}` to `POST /api/lobe` (the same auth and
origin check). `signoffAct` writes one `decision` line `{ts, op, ok, who, signoff, choice}` in pass-actions.jsonl, which
zeitgeistd claims.py `run` applies (`_answer_signoff`). Refused: a choice that is not apply or drop, a Sign-off that is not
pending, and a second answer before the lobe's next run (a tap newer than signoffs.jsonl). After the lobe rewrites the file,
a Sign-off still pending can be tapped again (the lobe refused the old tap).

**View (`trustCard` in `public/lobe.js`).** After Decisions ready, before Lobe health; also with no frame. Groups: Foreman,
Crews (an "Every crew" row, one row per model, most claims first, and a line with the Inspector's and build crews' numbers),
Subcontractors, World (world claims plus the top 5 sources by claims), then the Sign-offs. Each row is a Brier HP-bar gauge
(high is bad), claims counted and the 7-day trend (`↓ better`, `↑ worse`, `→ flat`). The S6a pixel look: the World view's
existing classes only (no new CSS, no style attribute); the header reuses the signpost icon because app.css is outside this
permit.

## ZG-39 and ZG-22 do not match (found while building)

ZG-39 wrote trust.py before ZG-22 existed and guessed the scoreboard's format. They do not match, so this card reads crews
from scoreboard.jsonl itself, and the Subcontractors row says why it is unknown.

1. **File kind.** trust.py `scoreboard_families()` reads `trust.scoreboard_path` as one JSON document (`_read_json`).
   scoreboard.ps1 writes JSONL, one line per `-Record` run (11 lines on this PC on 10-24). Pointed at it, trust.py fails to
   parse it and both families say `unreadable`.
2. **Shape.** trust.py wants top-level `{"crews": {name: {brier, n}}, "builders": {name: {brier, n}}}`. The scoreboard line
   has `brier: {value, claims, pending, inspector: {value, claims}, builder: {value, claims}, models: {model: {value, claims}},
   kinds: [{kind, model, value, claims}], missing}`. No `crews` or `builders` key, and `value`/`claims` instead of `brier`/`n`.
   Even one line parsed would give `no brier in the scoreboard`.
3. **Meaning of "builders".** In the scoreboard `builder` is the build crew's role (its "tests pass" claims). In the Glossary,
   builders (session subagents) are Subcontractors, and nothing scores them yet. trust.json's `builders` family can only be
   filled once something records their claims.
4. **World sources.** trust.json carries `sources_scored` and `sources_mean_trust` only, no per-source list, so "top 5 world
   sources" shows unknown with that reason. The card shows a `families.world.sources` list (`{id, brier | trust, n}`) once
   trust.py writes one.

Suggested fix (zeitgeistd, a later Floor): read the last line of scoreboard.jsonl, map `brier.models` to `crews`
(`value` -> `brier`, `claims` -> `n`), and either drop `builders` or fill it from a real subcontractor record.
