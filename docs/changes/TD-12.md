# TD-12: each Tower says how its Inspector runs

Floor TD-12 of Site TD (TD Pour 3), from `projects/tide/plans/multi-site-design-2026-10-23.md` section 2.5 and the Floor table.
Built in the private repo, merged into the multi-site stack and ported to tide in #11 (`docs/changes/port-132.md`). This note was
written after the port, from the code and tests on the #11 branch (review #11 F8: the port carried no TD-12 note).

## What it does

- `kitchen.repo.json` may carry an `inspector` block: `{ "local": "impacted" | "full", "ci": "quick" | "full" }`, validated by
  `kitchen/repo-config.ps1` like every other key (fail closed, the file named). `"local": "impacted"` needs `"ci": "full"` (a
  narrowed local run is only safe when CI runs everything); `ciTests` may be written ahead while `ci` is quick.
- `kitchen/stations/tests.ps1`: `"local": "impacted"` makes an order's own run an impacted one (as if `-Impacted`), and the step
  log says which plan ran ("tests: inspector: local full, ci quick"). No block = exactly as before.
- tide's own block is `local: full, ci: quick`: every suite runs sandboxed on this PC before a PR, CI is `ci.yml`'s quick checks.
  The design's default for a public Tower is `local: impacted, ci: full`; moving tide to it is the Owner's call (review #11 F6).

## Proof

- `tests/Test-RepoConfig.ps1` (the inspector checks: values, refusals, `ciTests`, tide's own block) and
  `tests/Test-TestsStation.ps1` (the station's impacted switch and its log line).

## L1-L4

- Person (the Owner): each project chooses between a faster local check and a full one, written next to its code.
- Business: CI minutes are spent where they are free or needed, not by habit.
- MSP: per-client test plans from one config file per repo.
- Community: none.
