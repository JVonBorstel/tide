# ZG-30: Glass box on the Board: lobe events in Activity and a health card with budgets

Floor ZG-30 of Site ZG. Size S. Branch `zg-30-glass-box`, built 2026-10-24 (MT). Stacked on ZG-13 (PR #102), which is on
ZG-09 (PR #92): it must merge after both. Depends on ZG-29 (merged in zeitgeistd as `e7a7d50`).

## What it does

**The lobe's lines in Activity (ZG30-1).** The Board tails `<lobe home>\events.jsonl` (ZG-29's mirror; the lobe home is
`ZEITGEISTD_HOME`, else `<Yard folder>\lobe`) beside the Yard's `events.jsonl`:

- The live pass sends each new lobe line as an `event` with `src: 'lobe'`. A new stream gets the newest 40 in its first message,
  and `/api/events` (the feed's history and backfill) carries the newest lobe lines too, merged by time.
- `public/lobe.js lobeSentence` words each type. GATE_DROP shows the rule (`rule dedupe.near_title`), or the score when there is
  no rule. SKIP shows the reason, named as RAM, model down, the governor or the Claude window when it matches, with the plain
  reason after it. BREAKER_TRIP is a **Stop-work order** line (Failures filter). SWEEP_START, SWEEP_DONE (scored, dropped,
  tokens, DLQ), INGEST, GATE_PASS, CSF_RECOMPILED, CSF_REFUSED and QUARANTINE have their own words. Any other type shows as its id.
- **ZG-29's Unresolved: repeat lines.** After a rotation the file is read again. The server keeps the keys it has sent (type, id
  and time, `lobeSent`) and never sends a line twice. The phone drops a repeat by the same key (`lobeEventKey`) in all four
  places it merges events. The time is part of the key so that a new store, whose ids start again, is not hidden.
- A missing or unreadable events file puts one line at the top of the feed: "Lobe events: unknown, <reason>".

**The Glass box card (ZG30-2).** The World view's last card (`glassHtml`, from `state.lobeGlass`). It shows even when there is
no frame, because that is when it matters most.

- **Head.** RED when the frame is older than 2 x the heartbeat's `everyMin` (2 x 2 h by default), or a Stop-work order is
  open. UNKNOWN, with each reason, when the events file or the heartbeat cannot be read. OK only when all of it was read and
  nothing is wrong.
- **Rows.**
  - Last sweep age.
  - Sweeps run vs skipped today, with each skip reason and its count.
  - Gate passed and dropped today.
  - Tokens today vs the ceiling (`gate.token_ceiling` from the lobe's config.json, else 150,000).
  - Queue.
  - DLQ.
  - Stop-work orders open at the last run, and which tripped in 24 h.
  - Last run, with its problem count.
  - Per band: last fetch, sources and items in 24 h.
- **The budgets line.** "Budgets: RAM N MB free (a sweep needs 2,500 MB) · tokens N of 150,000 today", plus a token gauge.
  RAM is `os.freemem()`, rounded to 50 MB. The need is the config `ram_min_mb`, else 2,500 (lobe.ps1's gate).
- **Today** starts at local midnight, as in gate.py `day_start_utc`. Tokens today sums `detail.tokens` of the stage-2 and stage-3
  CALL lines, which are the rows gate.py `tokens_today` sums. When the file starts after midnight, the counts say "at least".

**Where it comes from (ZG30-3: nothing on the event loop opens the database).** Three files: events.jsonl (read once, then only
new bytes; the first read is capped at the newest 4 MiB), the heartbeat (config `heartbeat_path`, else
`<lobe home>\heartbeat.json`, at most 64 KB) and config.json. There is no child process, no worker and no SQLite. A test reads
the block and checks this.

**Privacy: counts, ids and kinds only.** Every lobe line is cleaned again on the server (`lobeClean`, the same rules as
telemetry.py `clean_detail`): numbers and booleans; a SKIP reason only when it is plain words; kind keys only when id-shaped;
a taste target becomes null. The heartbeat's `error` text and `skipped` reasons never leave the server; only `failing` and a
count do.

**A flaky test found and fixed.** The first Test-PassApp run failed ZG-13's "a stale frame is skipped" check once. It passed 4 of 4
when run alone. The cause: the test writes two frames of the same size back to back. Within one Windows clock tick (about 16 ms)
they get the same mtime, so `sigOf` (size and mtime) sees the same file and the memo returns the old frame. The test now waits 40 ms
between the two writes (`test-lobe.mjs`). The same blind spot exists in the product, but only for two same-size writes within
16 ms. The next lobe write corrects it.

## Unknown or not verified

- **Queue depth has no file source.** `health --json` prints it, but the heartbeat does not carry it, and the Board never runs the
  lobe or opens its database. The row says "unknown" with that reason. It shows a number as soon as the heartbeat carries
  `queue.depth`. That is a small zeitgeistd follow-up: health.py `beat()` would add `queue` from telemetry.py's health_json.
- **Per-band Stop-work order state.** Breakers are keyed by breaker id, not by band, and the heartbeat has only the open count.
  The card shows the count plus the ids that tripped in 24 h. It does not show a state per band.
- Not run against a real lobe file. Only synthetic lines in telemetry.py's exact shape were used.
- The live Board on 7878 was not touched. No browser check was done; the markup is checked as strings.
- CI: see the PR.
