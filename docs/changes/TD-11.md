# TD-11: CI runs and minutes per Site; hold new PRs over budget

Floor TD-11 of Site TD (TD Pour 3), from `projects/tide/plans/multi-site-design-2026-10-23.md` section 2.2 and the Floor table; Owner's Q8 = yes.
Branch `ms-td11-ci-budget`, stacked on TD-9 (`ms-td9-site-closed`, PR #128) at `1d13bb6`, built 2026-10-24. Merges after #128.

## What it does

- **Count (chores):** `Invoke-ChoreCiBudget` (`kitchen/kitchen.ps1`), every 10 minutes within 20 s, counts this calendar month's (UTC)
  GitHub Actions runs (GitHub's own `total_count`) and billed minutes for every Tower the live orders, the registry's `towers` and this
  month's last count name (`kitchen/ci-budget-lib.ps1`, gh through `github-lib.ps1`). Billed as GitHub Free bills a private repo
  (`audits/go-public-scan-2026-10-23.md`): each job rounded up to a whole minute, Windows 2x, macOS 10x; a public Tower's runs are free
  (counted, 0 billed). A finished run is measured once (`ci-budget-cache.json`). Written to `<kitchen>\ci-budget.json`, with the
  account's shared private pool (2,000/month; `ciPrivatePoolMinutes` overrides) for show.
- **Budget:** `kitchen.json` `sites.<CODE>.ciMinutesPerMonth`: a whole number or `"unlimited"`. No budget = never held. A wrong value
  is a problem line and holds nothing.
- **Hold (Q8):** the pr station asks `Get-CiBudgetHold` before opening a NEW pull request; over budget = exit 11, asked again in 6 hours,
  with the reason. An open PR is still pushed to. The budget is read from the registry each time, so raising it lets PRs go at once.
- **Unknown (TD-EH-15's rule):** a failed GitHub read makes that Tower `unknown` with its reason; runs and minutes stay null (never 0)
  and an unknown count never holds. A measurement cut short is `partial`: what was measured is a lower bound, and only that can hold.
- **Board:** `server.mjs` `ciBudgetView` (nothing for another month's file); `public/ci-budget.js`: an alarm banner per Site over budget
  and one calm line with every Site's runs and minutes and the private pool.
