# ZG-45: Self card and the weekly self line

Floor ZG-45 of Site ZG. Size S. Branch `zg-45-self-card`, built 2026-10-24 on brain-monitor main `05a945e`.
Depends on ZG-34 (roadmap shadow) and ZG-23 (Time-to-Close), both zeitgeistd, and on ZG-25 (decision cards) and ZG-40 (Trust card). All are merged.
Permit: `pass-app/public/app.js`, `scripts/weekly-line.ps1`, `tests/Test-WeeklyLine.ps1`, `docs/changes/ZG-45.md`.

## In plain words

The World tab has a new Self card. It shows what the system is avoiding, what it got wrong, and how fast things close:

- Pours with 0 hours in 14 days, and how many of their Floors have no work order.
- Post-mortems that are due, and how many still wait for you.
- Time-to-Close medians over 7 and 30 days.
- The trust line.

The World tab's badge counts the shadow Pours plus the post-mortems still waiting for you. The weekly line in the performance plan now has a second line, the self line. It holds the build standard's four numbers plus `shadow pours: N, post-mortems due: N, foreman brier: X`. Where there is no data, it says "unknown" and why.

Your Charter isn't written yet. The card says so plainly: "The Owner's Charter is not written yet, so the Charter domains below are the example's, not yours." The weekly line adds `Charter: not written yet (the shadow uses the example)`.

## What it does

**The card (`pass-app/public/lobe-self.js`, new).** It is pure and uses only data the World view already has. The server is not changed:

| Row | Source |
|---|---|
| Shadow Pours, Floors with no order | csf `2_endogenous_self_state.shadow_blindspots`: the pour lines from zeitgeistd `connectors/roadmap.py:220` |
| Blueprints not read | the same list: `<name> roadmap: unreadable / stale (why)` (`roadmap.py:184, :191`) |
| Charter domains with 0 h | the same list: ZG-23's blindspot lines (`INCOME_TRACK: 0 h in 14 d; unmet SYSTEM`) |
| Post-mortems due, still waiting | `state.lobeOwner.decide` (flags.json, ZG-25). Without it: csf `meta.counts.post_mortems_due` |
| Time-to-Close | csf `meta.ttc_median_hours` (`ttc.py compact`): open loop, Sign-off and decision, over 7 and 30 days |
| Trust | csf `meta.trust` (the lobe's Foreman line, ZG-39) and the crews' Brier from `state.lobeOwner.trust.board` (ZG-40) |

The card sits after Trust and before Lobe health, and only with the Owner part, like Trust. It also shows when there is no frame. Its rows then say unknown with the frame's reason.

**What it will not claim:**

- **"0 shadow Pours" when nothing was read.** roadmap.py writes a line only for a Pour with 0 Yard hours, so an empty list could mean "all fine" or "never read". With no Blueprint line at all, the count is `unknown (no Blueprint line in the frame: every Pour got hours, or no Blueprint was read)`.
- **A count when the Yard's hours are unknown, or when the only Blueprint could not be read.** Both are unknown too, with the reason.
- **An exact count from a trimmed frame.** When csf.py trimmed the frame (`meta.trimmed` > 0), counts say "at least".
- **Answers this month, or the calibration delta.** Both are unknown. The Board sees a post-mortem answer only until the lobe's next run. The held rate before and after (`prior_calibration_delta`, decisions.py) is kept only in the lobe's database, and neither flags.json nor csf.json carries it. Getting them onto the Board needs a zeitgeistd change: flags.json would carry the month's answers and the delta.
- **Screen minutes.** Unknown: nothing measures them (the same as ZG-23).

The display words follow the Glossary: Pours, Floors, Blueprint, Sign-off, Foreman, Owner. A pour id is shown exactly as the file spells it (`GW W4`), so Demo Project keeps its own words until its rename date. roadmap.py's "cooking" is shown as "building". Every frame word is escaped. Lines in shapes the card does not read are counted, never shown. The card uses only classes the World view already uses: no new CSS, no style attribute.

**app.js** only wires the badge: `selfCount(s.lobe, s.lobeOwner)` into `#count-world` in `renderChrome`.

**The self line (`scripts/weekly-line.ps1`).** It is written right after the weekly line, with the same date, so the "not due" check is unchanged. For example:

```
- 2026-10-24: self · broken mains 0 · false undos unknown (<the scoreboard's reason>) · silent failures unknown (<reason>) · minutes Floor start to merge 32.5 over 4 Floors · shadow pours: 2, post-mortems due: 1, foreman brier: 0.08 · Charter: not written yet (the shadow uses the example)
```

- **The four numbers.** They come from scoreboard.ps1's `standard` (ZG-22), each with the scoreboard's own reason when null.
- **The lobe part.** It reads `<LobeHome>\csf.json`, where `<LobeHome>` is `ZEITGEISTD_HOME`, else `<kitchen>\lobe`, the same as server.mjs `lobeFile`. A frame older than 4 h is not counted. The line has counts and fixed words only: no pour id, loop, decision or Yard text. A trust line in a shape the script doesn't know is `unknown`, and its text is never copied.
- **No push.** The line never pushes, so notify.ps1 is not involved.
- **ZG45-3.** It writes only the plan file, as before: no memory file and no other file.
