# W0: stop the bleeding (Tide arch-10-22, wave W0)

Since PR #37, ticks took 160-340 s. The slow ticks looked like the PC had slept, so they moved every running step's clock. One hung step (J207) held a slot for hours because hung checks were off. A torn merge-train file read as "no train". This change, plus the dedupe already merged in PR #44, fixes all four:
- The freeze view is rebuilt only when a repo's `kitchen.repo.json` changes, or every 10 minutes. `status` reads `freeze.json` and runs no git.
- The sleep gap is this tick's process start minus the previous tick's recorded end (`lastTickEnd`). A tick over 60 s logs `tick.slow {sec, phase, phaseSec}`.
- The hung check is on by default: 900 s when the step sets none, `-1` turns it off. A step counts as alive while its heartbeat, its log or its cook's activity file changes. A heartbeat `<time> quiet=<sec>` covers a bounded silent wait (a test suite, a cook run).
- When `merge-train.json` cannot be read, the merge is held (exit 11). Train writes are now atomic.

Files: `kitchen/freeze-lib.ps1`, `kitchen/kitchen.ps1`, `kitchen/stations/merge.ps1`, `kitchen/stations/tests.ps1`, `kitchen/stations/mutate.ps1`, `kitchen/agent-step.ps1`, `kitchen/cooks/local.ps1`, `kitchen/BUILDING.md`, `tests/Test-Freeze.ps1`, `tests/Test-KitchenSupervisor.ps1`, `tests/Test-KitchenMerge.ps1`.

## Effect
- L1 (person): `status` (kitchen_status, jk) no longer waits on git. Bench, same moment, same state copy: 1,819 ms on main, 1,345 ms with this change. A hung step frees its slot about 15 minutes after its last sign of life.
- L2 (business): no more false sleep shifts, so step limits mean what they say. To verify: count `supervisor.resumed` and `tick.slow` in events.jsonl over the 24 h after the merge.
- L3 (MSP): the merge lock can no longer let two merges in on a damaged file.
- L4 (community): `tick.slow` is a permanent probe that names the slow phase.

## Not done
- Per-station hungSec from heartbeat history (W1/R5). 900 s is a floor.
- A tick run in-process by a long-lived pwsh (tests, kitchen-api inside a tick) counts from that process's start. That can only hide a sleep, never invent one, and it can log `tick.slow` for an old process.
