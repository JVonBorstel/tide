# ZG-13: Charter and taste cards on the Board, and the morning brief's lobe line

Floor ZG-13 of Site ZG (ZG Pour 2, size M, depends on ZG-09 and ZG-12). Branch `zg-13-charter-cards`, built 2026-10-24 (MT)
on top of ZG-09's branch (`zg-09-world-view`, PR #92). Repo brain-monitor; zeitgeistd is not touched.

## In plain words

The World tab now lets the Owner act, by tapping, and only by tapping:

- **Charter card.** Today it says plainly: "Your Charter isn't written yet." The lobe's EXAMPLE seed is folded away under
  "The lobe's EXAMPLE seed (placeholders, not yours)", so it never looks like the Owner's. Under it, "Write your Charter":
  a mission order line and one box per domain (domain, objective, hard constraint, depends on). **Save and lock** asks
  once, then the Board writes CHARTER.md and one `charter-locked` line with the file's fingerprint (sha256). The card
  then says "Locked by you ... The lobe imports it on its next run; the EXAMPLE badge goes then." A later hand edit shows
  red until the Owner locks again.
- **Your taste card.** Up / Down / Mute under every signal, a "Focus on ..." box, the Owner's recent taps, and proposals
  from a crew or the Foreman as Apply / Drop cards that change nothing until tapped.
- **Morning brief.** One "Lobe:" line with counts only (decisions ready, post-mortems due, world signals in 24 h, the
  frame's age), or red "Lobe: skipped, <why>" when the frame is missing or stale.

## What it does

- **Server (`pass-app/server.mjs`), one block after the lead code:**
  - Reads only: `charterView()` (CHARTER.md, at most 256 KB, parsed in charter.py's format, sha256 compared with the
    newest `charter-locked` line: `none`, `unlocked`, `locked`, `changed`, `invalid` or `refused`), `proposalsView()`
    (`<ZEITGEISTD_HOME>\proposals.jsonl`, taste ops only, minus the ones a `decision` tap answered and the ones over 7
    days old), `tasteView()` (the Owner's own taste taps by key). All files, memoized by `sigOf`; no child process, no
    database. `state.lobeOwner` carries them, so a tap reaches open phones as a patch.
  - Writes only on a tap: `POST /api/lobe` sits in the same block as `/api/action` (approvals): `authed`, the origin
    check, JSON only, the 64 KB cap. Ops: `taste-up`, `taste-down`, `taste-mute`, `taste-focus` (`key`, focus `weight`
    0.1..3.0), `decision` (`proposal`, `choice` apply / drop, only for a proposal still waiting), `charter-save`.
    Each successful tap is one line in pass-actions.jsonl in zeitgeistd `actions.tap_line()`'s shape:
    `{ts, op, ok: true, who, ...fields}`. A refused tap is audited as `lobe-<op>` with `ok: false`, never its words.
    The same tap twice within 3 s writes once.
  - `charter-save` builds CHARTER.md from the fields (one line each, control characters out), refuses the EXAMPLE seed's
    wording, writes temp + rename, then appends `{"op":"charter-locked","sha256":<sha256 of the bytes written>,"by":"Owner"}`.
  - `brief()` gains `lobe: {decisionsReady, calibrationQuestions, postMortemsDue, signals24h, csfAgeMin, skipped}`
    from the frame's counts. `calibrationQuestions` is `null`: the frame has no such count until ZG-27.
- **View (`pass-app/public/lobe.js`):** `worldHtml(view, {now, owner})` adds the Owner's cards when `owner` is given
  (without it, ZG-09's read-only view is unchanged). With no frame, the plain line is followed by the Charter and taste
  cards, since writing a Charter needs no frame. `wireWorld()` is the only place that posts, inside click and submit
  handlers; `worldEditing()` holds the live redraw while the Owner types. `briefLobeLine()` builds the brief's line.
- **Hooks:** `app.js` (import, one `wireWorld` call, the redraw guard and `owner` in `renderWorld`, one brief line),
  `app.css` (one block at the end, tokens only, no new colours).

## Decisions (each a choice, not a guess)

- **The Board reads the Charter file and its own taps, not the weights.** Taste weights live in the lobe's database;
  the Board never opens it (ZG09-3: no database on the event loop). The card shows the Owner's taps and says the lobe
  keeps the weights.
- **`by: "Owner"`**, not a person's name, in the `charter-locked` line (the Glossary's word; ZG-12 reads `by` only to
  refuse agent words). `who` is the signed-in Tailscale login, or `key` for a pass-key session, as `audit()` writes.
- **Per-signal taps key the signal's title.** csf.json names no source for a signal (csf.py), so "mute source" mutes
  the title as a taste key until the frame carries a source name.
- **CHARTER.md path:** `ZEITGEISTD_CHARTER`, else `%USERPROFILE%\gemini-brain\projects\zeitgeistd\CHARTER.md`
  (the file ZG13-1 names). A path inside a protected folder is neither read nor written.
- **Proposal age** is judged from the proposal's own `ts` on the Board; the lobe's own expiry (from when it stored the
  proposal) is the one that counts. A proposal with no `ts` is shown.

## Unknown or not verified

- **Tier-2 raw text per item (ZG13-3) is not built.** The frame carries no item ids, and the Tier-2 reader is the
  lobe's search CLI over its database (`--raw <item_id>`), which the Board does not call. It needs a file-only route
  or a later Floor; no "this PC only" badge is shown because no raw text is shown.
- How the editor looks on a real 360 px phone: not opened in a browser in this build (markup checks only; the CSS has
  no fixed width).
- The lobe's `charter.path` setting must point at the same CHARTER.md (ZG-12 "For the Owner" step 1), and a standing order
  must run `actions run` (ZG-07 / ZG-33) before any tap is applied.
