# I192: diff-scoped test selection

Repair's loop runs now test only the suites the change touches (`tests.ps1 -Impacted`, mapped from the diff against `.kitchen/BASE`). A narrowed run ends `PARTIAL PASS`, never `ALL PASS`, and repair then runs every suite once before review. Shared core files, unmapped files and an unknown change list run everything and say why. Table and rules: `kitchen/BUILDING.md`, "Which suites run".

Files: `kitchen/stations/tests.ps1`, `kitchen/stations/repair.ps1`, `kitchen/BUILDING.md`, `tests/Test-TestImpact.ps1`.

## Effect
- L1 (person): shorter waits in repair rounds, because each round runs a few suites first. Size of the saving: UNVERIFIED; measure it from the per-suite seconds in `TESTS.txt` after a few jobs.
- L2 (business): fewer bounded-run minutes per repaired change. Not measured yet.
- L3 (MSP): the safety gate is unchanged. Only a full run writes the job's result, so auto-merge cannot trust a narrowed run. `kitchen/stations/` stays protected, so this change needs Jordan's tap.
- L4 (community): a documented, plain mapping from changed files to suites that other repos can copy.
