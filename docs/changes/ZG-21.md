# ZG-21: Verify bridge: due public claims become research work orders; answers come back as resolutions

Floor ZG-21 of Site ZG. Size S. Branch `zg-21-verify-bridge`, stacked on ZG-17 (PR #106), built 2026-10-24 (MT). Depends on
ZG-20 (zeitgeistd, merged as 12db9f4) and ZG-07 (merged).

## What it does

- **`lobe.ps1 -Cmd verify`** (kitchen/stations/lobe.ps1). No model, no RAM or Ollama gate, no GPU lock: the Cloud crew does the web
  work. Two parts, under one lock (`Local\brain-lobe-verify`), so two runs never file the same claim:
  1. **Collect.** For each work order it filed whose answer is saved (`<kitchen>\lobe\verify\<job>.md`, the Spec's `SaveTo`), it
     reads the answer (`Read-VerifyAnswer`, lobe.ps1:249) and calls
     `claims resolve <id> <verdict> --by auto --sources <urls> <answer file>` (lobe.ps1:271).
     - The verdict is the one `VERDICT:` word: VERIFIED, REFUTED, GOALPOST_MOVED or UNKNOWN. No verdict, two different ones, or a
       word that is not one of the four: **UNKNOWN, with only the answer file as its source** (kept as a note).
     - The URLs come only from the last `SOURCES` section: http(s), a host, no user name or password, no repeats, at most 9. The
       answer file is the 10th source. Links in the body are not sources.
     - **zeitgeistd decides what counts as evidence.** When it refuses a verdict (exit 3, e.g. the only URL is the claim's own item),
       the Step does not force it: it resolves UNKNOWN with the file kept (lobe.ps1:307). The Step never resolves `--by owner` and
       never marks a claim true itself.
  2. **File** (not with `-Only collect`). It reads `claims due --public --json` (lobe.ps1:324), without writing that list to the
     Step log. Only a claim whose `privacy` is exactly `P0` becomes a work order (lobe.ps1:332). P1, P2 or a claim with no class is
     dropped and counted as `not_public`, even if the list holds it. A list that does not say `public: true` files nothing (exit 1).
     - At most **3 work orders a day** (local date, lobe.ps1:231). The rest wait (`waiting=N`) for the next day.
     - Each is cooked on Spec `lobe-verify` through kitchen/cook.ps1 (lobe.ps1:339). Its only value, `question`, is
       `Claim: <statement>` plus `Made: <date ingested>` and `Due: <due date>` (`Get-VerifyQuestion`, lobe.ps1:275). No claim id,
       source, source name, item URL, Charter, loop or history.
  - The list of work orders is `<kitchen>\lobe\verify-orders.json`: claim id, work order, filed time, state (`filed`, `resolved`,
    `closed`, `failed`, `expired`), the verdict and the answer path. Never the statement. It is written right after each filing.
  - A work order with no saved answer after 7 days is let go (`expired`); its claim may be filed again.
  - It ends `lobe: verify filed=.. resolved=.. unknown=.. waiting=.. expired=.. not_public=.. too_long=..`, then
    `lobe: verify done items=N dropped=N ms=N`. A failed part: `lobe: verify FAILED (...)`, exit 1.
- **When it runs.** After every rem run that exits 0 (daily at 4 am, the lobe-rem standing order), before ZG-17's push
  (lobe.ps1:407). A verify failure never changes rem's result. Until zeitgeistd has `claims.py`, rem says `verify not run`.
- **Spec `kitchen/recipes/lobe-verify.json`.** A copy of `research.json`: one research step (Cloud crew, `WebSearch,WebFetch`,
  `mustMatch: SOURCES`), with `public: true`, a fixed prompt asking for one `VERDICT:` line, and `SaveTo
  {{kitchen}}\lobe\verify\{{job}}.md`. A second step runs `lobe -Cmd verify -Only collect`, so the answer goes back as soon as it is
  saved. Collect only: a work order never files more work orders.
- **ZG21-3: not built, by design.** Search-engine chains and CAPTCHA cooldowns (document patch 22) are not built. The Cloud crew's
  own web tool is the engine.

## Decisions (each is a choice, not a guess)

- **P0 only, checked again here.** zeitgeistd's `due --public` already drops P1 and P2. The Step drops anything not exactly P0 as
  well, so a bug there cannot send a personal claim to a Cloud crew.
- **Daily rem, not every sweep.** With 3 a day, once a day is enough. Sweeps wait on RAM and Ollama; verify needs neither, but it
  needs no Spec of its own this way. When rem waits (low RAM), filing waits a day. Answers still come back through each work order's
  own collect step.
- **A refused verdict becomes UNKNOWN,** not a retry. UNKNOWN can still be resolved later (ZG-20), by a new answer or the Owner.
- The prompt says "the Owner" (GLOSSARY), where research.json says Jordan.

## Unknown or not verified

- **No real claim was checked.** The live Yard is paused, and no real gate claim has come due yet.
