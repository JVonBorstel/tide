# House rules for brain-monitor code

PowerShell 7 and Node ESM (no dependencies). Rules come after `kitchen/CREED.md` and `AGENTS.md`. Each rule says how it is checked.
"Checked by script" means `scripts/check-standards.ps1`, which `tests/Test-Standards.ps1` runs, and the Yard's tests Step (code: `kitchen/stations/tests.ps1`) runs that suite on every work order.
Names: `gemini-brain/projects/tide/naming/GLOSSARY.md`. The Inspector is the review step (code: `taster`).

**Ratchet.** Today's known violations are listed in `kitchen/lint-baseline.json`. The check fails on a violation that is not listed, and on a listed file with more hits (bare python, URL secrets, analyzer errors). A listed oversize file that grows prints a `WARN:` line (file, baseline, now) and does not fail, because open work orders still add to those files; splitting them is its own work order. It prints the baseline count every run. When you fix a listed file, delete its line from the baseline. Re-record with `scripts/check-standards.ps1 -WriteBaseline` only in a PR that says why in "# In plain words".

| # | Rule | How it is checked |
|---|------|-------------------|
| 1 | **Size.** No code file over 600 lines (`.ps1`, `.psm1`, `.mjs`, `.js` under `kitchen/`, `scripts/`, `pass-app/`, `tests/`). Split by seam: a reason, two owners, a view. | Script (`size`). A new file over the cap fails; a listed file that grows only warns. |
| 2 | **Header.** The first two lines of every script are comments: line 1 what the file owns, line 2 who calls it. `#` in PowerShell, `//` in JavaScript. A `#!` line may come first; `#requires` and `<# #>` do not count. | Script checks the shape (`header`). Whether the words are true is checked by the reviewer. |
| 3 | **Bounded runs.** Every test suite and every agent or long command runs through `scripts/run-bounded.ps1` (time and memory caps). No `Start-Job`, no `Start-Process` without `-Wait`, no `[Diagnostics.Process]::Start`, no scheduled task. | `kitchen/stations/lint.ps1` flags these on the lines a work order adds. |
| 4 | **No bare python.** Never `python`/`python3`: on this PC it is the Windows Store stub. Use `uv run` with `UV_PYTHON_PREFERENCE=only-managed`. | Script (`python`) over the whole repo, and `kitchen/stations/lint.ps1` on added lines. |
| 5 | **No secrets in URLs.** No key, token, password or signature as a literal URL query value; build secret-looking strings at runtime and send them in a header. | Script (`urlsecret`), and the CI secret scan (`scripts/ci-quick-checks.ps1`). |
| 6 | **PowerShell analyzer clean.** No PSScriptAnalyzer findings at Error severity. | Script (`analyzer`) when `Get-Module -ListAvailable PSScriptAnalyzer` finds it. Otherwise it prints one `SKIP:` line; nothing is installed. |
| 7 | **One test per acceptance line.** Each acceptance line has a test named after it, no more. Suites are `tests/Test-*.ps1`, under 30 s, self-cleaning, and print `<Name> tests: N passed, M failed`. | The Inspector (code: `taster`, the review step) checks this against the work order, and the tests Step runs every suite. |
| 8 | **PR shape.** The body starts with `# In plain words` (3-6 short sentences for Jordan), then `## What changed`, `## Proof` (suites run, with counts). | `.github/pull_request_template.md`. `tests/Test-Standards.ps1` checks that the template keeps that shape; the Inspector checks the PR. |
| 9 | **Change notes.** Every change note (PR body, `kitchen/EVOLUTION.md` entry) says the L1-L4 effect: on the person, the business, the MSP, the community. Write "none" where there is none. | Template section; the Inspector checks it. |
| 10 | **Map.** `kitchen/MAP.md` lists every code file with its lines, header and functions. Re-run `scripts/make-map.ps1` in any PR that adds, removes or renames code. Read the map before opening files. | By hand. It is not tested for freshness, so that parallel work orders do not fail each other. |
| 11 | **Short functions, shallow nesting.** No function over 80 lines; no control block (if, loop, switch, try) nested more than 5 deep inside one function. A nested function or a `ForEach-Object { }` block starts the count again, like ESLint `max-depth`. | `scripts/quality/metrics.ps1` (`longfn`, `nesting`), ratchet over `kitchen/quality-baseline.json`: a new long function or deep file fails, a baselined one that grew warns. PowerShell through the parser; JavaScript through `scripts/quality/js-metrics.mjs`, a tokenizer (strings, comments, templates, regex literals) plus a brace pass. |
| 12 | **No copy-paste.** The same 6 code lines (trimmed, spaces collapsed; blank, comment-only and bracket-only lines ignored) must not appear twice in the repo. Share them through one function. | `scripts/quality/metrics.ps1` (`dup`), same ratchet; the FAIL line names the other copy (file:line). |
| 13 | **Analyzer does not get worse.** A PowerShell file a change touches must not gain PSScriptAnalyzer Warning or Error findings of any rule, compared with its base version. Left out, with the reason in the script: Write-Host (suites print with it), ShouldProcess, singular nouns, approved verbs, BOM. | `scripts/quality/metrics.ps1 -ChangedSince <ref>`; CI passes the PR base. Runs only when the module is already installed (it is on Jordan's PC, 1.25.0); otherwise one `SKIP:` line. Never installs. |

Tools: `scripts/check-standards.ps1` (the ratchet), `scripts/quality/metrics.ps1` (rules 11-13; `-Report <json>` writes every file's numbers, `-WriteBaseline` re-records only in a PR that says why; `tests/Test-Quality.ps1` and the CI `quality` job run it), `scripts/make-map.ps1` (the map), `scripts/dead-code.ps1` (lists PowerShell functions whose name appears nowhere else in the repo; report only, weekly by hand).
